# Aetheris – Phase 12.2: Conversation Intelligence & Follow-up Resolution

You are a Principal AI Systems Architect.

The Memory System is complete.

The Context Relevance Engine is complete.

The Search Pipeline is complete.

The problem is that Aetheris treats every user message as an independent request.

Example

User:
Talk about kingdoms.

Assistant:
(Explains kingdoms.)

User:
Elaborate.

Assistant:
"What would you like me to elaborate on?"

This is incorrect.

The assistant should recognize that "Elaborate" refers to the previous assistant response and continue explaining kingdoms.

---

# Objective

Implement a Conversation Intelligence Engine that understands conversational references and follow-up requests.

The system should resolve what the user is referring to before the prompt is sent to the LLM.

---

# Existing Architecture

Do NOT redesign the existing architecture.

Add Conversation Intelligence between Conversation Retrieval and Context Builder.

# Conversation Intelligence Responsibilities

The engine must determine whether the current user message is:

• A brand new topic

• A continuation

• A clarification

• A comparison

• A follow-up

• A correction

• A refinement

• A reference to earlier discussion

# Reference Resolution

When a follow-up request is detected,

identify the most likely conversation target.

Priority

1. Previous assistant response

2. Previous user question

3. Previous conversation segment

4. Relevant conversation history

Assistant:
...

User:
Give examples.

Recursion

NOT

General programming.

---

# Ambiguity Handling

If the reference cannot be resolved confidently,

then ask a clarification question.

Example

User

Explain AI.

↓

Explain Python.

↓

Elaborate.

Possible references

AI

Python

If confidence is low,

ask

"Would you like me to elaborate on AI or Python?"

Only ask for clarification when multiple valid references exist.

Never ask for clarification if the previous context clearly identifies the topic.
